## Introduction

At NASCOMSOFT EMBEDDED LTD, all submitted work must be reviewed and verified before it can be officially marked as completed.

The Project Manager is responsible for coordinating this process, confirming that deliverables meet the assigned requirements, and updating the Task Assignment Dashboard.

Employees are responsible for submitting their work, providing any information needed for verification, and addressing corrections when requested.

This guide explains how submitted work is reviewed, how task completion is confirmed, and what must happen before a project can be officially closed.

> [!IMPORTANT] Submission Is Not Completion  
> A task is not officially completed simply because an employee has finished the work or uploaded the deliverables.
> 
> **Only the Project Manager confirms task completion and updates the official task status.**

---
## 1. How the Review Process Works

Once an employee has submitted their deliverables and notified the Project Manager, the work becomes available for review.

The standard process is:

1. **Employee submits work:** The employee uploads the required deliverables to the appropriate pCloud submissions folder or company GitHub repository.
2. **Employee notifies the Project Manager:** The notification identifies the project, task, and location of the submitted work.
3. **Project Manager reviews the submission:** The submitted work is checked against the task requirements.
4. **Feedback is provided:** The Project Manager either accepts the work or requests corrections or additional information.
5. **Task status is updated:** Once the work has been accepted, the Project Manager updates the Task Assignment Dashboard.

Where necessary, the Project Manager may consult the employee responsible for the work or other relevant technical contributors during verification.

---
## 2. What Is Checked During Verification?

The exact verification requirements depend on the nature of the assigned task.

Generally, the review considers whether:
- The submitted work addresses the assigned task.
- All required deliverables have been provided.
- The files are accessible and properly organized.
- The work meets the relevant project specifications or instructions.
- Required tests, checks, or supporting evidence have been provided.
- Any required documentation has been completed.
- The deliverables have been submitted to the appropriate company platform.

### Examples of Verification

| Task Type                        | Possible Verification Checks                                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Software or firmware development | Source code is available in the company GitHub repository, required functionality has been demonstrated or tested, and necessary supporting files are present |
| Circuit design                   | Design files and schematics are provided, and the design addresses the assigned requirements                                                                  |
| Research                         | Required findings, references, and reports are submitted                                                                                                      |
| Testing                          | Test procedures, results, and relevant evidence are provided                                                                                                  |
| Technical documentation          | Documentation is sufficiently complete, accurate, and accessible for its intended purpose                                                                     |

These examples are not exhaustive. The Project Manager determines the relevant verification requirements based on the task assignment.

## 3. Reviewing pCloud Submissions

Non-code deliverables are submitted through the dedicated pCloud submissions folder linked in the Project Brief.
### Review Procedure

1. Open the relevant project submissions folder.
2. Locate the files submitted by the employee.
3. Confirm that the files correspond to the assigned task.
4. Review the contents against the expected deliverables.
5. Determine whether the work is acceptable or requires corrections.

### Handling Accepted Files

Once a submission has been accepted, the Project Manager moves the approved files from the submissions folder into their appropriate permanent location within the project's pCloud folder structure.

This ensures that the project's main resource folders contain reviewed and accepted deliverables.

Employees should not move their own submissions into permanent project folders unless explicitly authorized.

> [!info] Purpose of the Submissions Folder  
> The submissions folder serves as a temporary location for work awaiting review.
> 
> It is separate from the project's permanent collection of accepted resources.
### Handling Files Requiring Corrections

If a submission does not meet the assigned requirements, the Project Manager provides feedback and requests the necessary changes.

The employee is expected to correct the work and submit an updated version for review.

## 4. Reviewing GitHub Submissions

Source code and related version-controlled files are maintained in the company's GitHub repositories.

Employees working on code-related tasks must provide the Project Manager with sufficient information to locate and review their submitted work.

This may include:
- The project repository link
- The relevant branch
- The commit reference
- A pull request link, where applicable
- Relevant testing or demonstration information

### Review Procedure

1. Locate the submitted work in the appropriate company GitHub repository.
2. Confirm that the required source files and related resources are present.
3. Check that the submitted work addresses the assigned task.
4. Review available test results or request a demonstration where necessary.
5. Determine whether the deliverables are acceptable or require further changes.

The Project Manager may involve relevant technical contributors in evaluating the work.

> [!IMPORTANT] Repository Access and Task Approval  
> The designated GitHub Administrator manages access to the company's repositories.
> 
> The Project Manager remains responsible for confirming whether the submitted work satisfies the assigned task requirements.

Approved source code remains in the appropriate company GitHub repository. It does not need to be transferred to pCloud as part of the standard workflow.

---
## 5. Corrections and Resubmissions

Not every submission will be accepted on its first review.

A submission may require corrections because of missing files, incomplete requirements, technical errors, insufficient documentation, or other identified issues.

When corrections are required:

1. The Project Manager communicates the issues that need to be addressed.
2. The employee reviews the feedback and makes the necessary changes.
3. The employee resubmits the corrected work through the appropriate platform.
4. The employee notifies the Project Manager that the revised deliverables are ready.
5. The Project Manager reviews the updated submission.

This process continues until the work satisfies the assigned requirements or further instructions are provided.

**A request for corrections does not constitute task approval.**

## 6. Updating Task Completion Status

The [Task Assignment Dashboard](https://nascomsoft.github.io/01-dashboards/tasks-assignment-dashboard/) provides the official overview of assigned work and its completion status.

The Project Manager is responsible for maintaining this information.

### When a Task Can Be Marked as Completed

A task may be marked as completed when:

1. The required work has been submitted.
2. The deliverables have been reviewed.
3. Any necessary corrections have been addressed.
4. The Project Manager has confirmed that the task requirements have been satisfied.
    

Employees must not independently change their official task completion status.

### Tasks That Are Not Yet Complete

A task should not be marked as completed if:

- Required deliverables are missing.
- The work has not yet been reviewed.
- Corrections are still outstanding.
- Required tests or supporting evidence have not been provided.
- Required documentation remains incomplete.

> [!IMPORTANT] Official Status  
> The Task Assignment Dashboard reflects the Project Manager's verified assessment of task completion, not merely an employee's report that work has been finished.

## 7. Documentation as Part of Project Completion

Technical documentation is an important part of NASCOMSOFT's project workflow.

Depending on the project, documentation may include:

- Project specifications and technical explanations
- Software setup and usage instructions
- Hardware design descriptions
- Circuit diagrams and supporting explanations
- Testing procedures and results
- Maintenance or troubleshooting information
- Other documentation required by the project

Documentation may be assigned as a standalone task or included among the deliverables for another task.

### Documentation Verification

When documentation is required, the Project Manager must confirm that:

1. The required documentation has been submitted.
2. It accurately describes the relevant work.
3. It contains sufficient information for its intended users.
4. It is stored in the appropriate company location.
5. Any necessary corrections have been addressed.

> [!IMPORTANT] Documentation Is Required for Project Closure  
> A project must not be officially closed while its required documentation remains incomplete or unverified.
> 
> Completing the technical implementation alone does not automatically mean the entire project is complete.

Detailed expectations for writing project documentation will be addressed in a separate [[Project Documentation Guidelines\|Project Documentation Guidelines]] guide.

## 8. Project Completion and Closure

Individual task completion and overall project completion are not the same.

A project may contain several tasks assigned to different employees, and some tasks may be completed while others remain outstanding.

Before a project is officially closed, the Project Manager must confirm that:

- All required project tasks have been completed and verified.
- Required non-code deliverables are stored in their appropriate permanent pCloud locations.
- Required source code is available in the appropriate company GitHub repositories.
- Necessary testing or other verification activities have been completed.
- Required project documentation has been submitted and verified.
- Outstanding corrections or required deliverables have been resolved.

Only after these conditions have been satisfied can the Project Manager confirm that the project is ready for closure.

> [!info] Project Knowledge and Continuity  
> Properly stored code, project files, and documentation allow future employees to understand, maintain, troubleshoot, or extend completed projects without relying entirely on the original contributors.

## 9. Weekly Review and Accountability

NASCOMSOFT conducts weekly task review meetings on **Mondays**.

These meetings provide an opportunity to assess completed work, discuss outstanding assignments, and identify issues affecting project progress.

Employees should be prepared to:

- Explain work completed during the previous week.
- Identify deliverables already submitted for review.
- Discuss outstanding corrections or incomplete tasks.
- Explain delays and challenges encountered.
- Provide relevant updates on ongoing work.

The Project Manager uses the verified task records and submitted deliverables to assess progress.

**Employees should not wait until Monday to submit completed work or report urgent blockers.**

## 10. Frequently Asked Questions

**Does uploading my work mean the task is completed?**

No. The task must be reviewed and accepted by the Project Manager before its official status is updated.

**Who updates the Task Assignment Dashboard?**

The Project Manager.

**What happens after my pCloud submission is approved?**

The Project Manager moves the accepted files from the submissions folder to their appropriate permanent project location.

**What happens after my GitHub submission is approved?**

The accepted source code remains in the appropriate company repository, following the project's repository workflow.

**What if my work requires corrections?**

You must address the feedback, resubmit the updated deliverables, and notify the Project Manager.

**Can a project be closed if the code works but the documentation is incomplete?**

No. All required documentation must be completed and verified before the project can be officially closed.

**Can I mark my own task as completed?**

No. Official task completion is confirmed and recorded by the Project Manager.
