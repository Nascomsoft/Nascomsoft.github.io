## Introduction

At NASCOMSOFT EMBEDDED LTD, employees are assigned tasks based on ongoing project requirements and company priorities.

These tasks may involve software development, circuit design, research, technical documentation, hardware development, testing, or other project-related activities.

Every employee is responsible for understanding their assigned tasks, completing them within the specified deadlines, and preparing the required deliverables for review.

This guide explains how to approach assigned tasks, organise your work, and communicate any challenges encountered during execution.

> [!danger] Before You Begin  
> Make sure you have reviewed your weekly task assignment and obtained the necessary project resources.
> 
> If you have not done so, read [[05-Inbox/accessing project resources\|Accessing Project Resources]] first.

---
## 1. Understanding Your Task Assignment

Before starting any task, carefully review the information provided in your weekly assignment.

Your task assignment may contain:

- **Project Name:** The project associated with the assigned task.
- **Task Description:** What you are expected to accomplish.
- **Date Assigned:** When the task was assigned.
- **Due Date:** When the task is expected to be completed.
- **Priority:** The relative importance of the task (High, Medium, or Low).
- **Further Task Breakdown:** Additional instructions or smaller activities required to complete the task.
    
### What You Should Do

1. Visit the [Task Assignment Dashboard](https://nascomsoft.github.io/01-dashboards/tasks-assignment-dashboard/).
2. Open your weekly task assignment note.
3. Review all tasks assigned to you.
4. Identify the deadlines and priorities associated with each task.
5. Read any additional instructions or task breakdowns provided.
6. Confirm that you understand the expected outcome before beginning.

> [!IMPORTANT] Task Clarification  
> If a task description is unclear or you are unsure about the expected deliverables, contact the Project Manager for clarification before proceeding.
> 
> Do not make assumptions that could lead to unnecessary work or incorrect results.

---
## 2. Planning and Executing Your Work

Once you understand your assignment, organize your work to ensure that it can be completed effectively and within the specified deadline.

### Recommended Approach

1. **Identify the expected outcome:** Understand what must be delivered when the task is completed.
2. **Review available resources:** Check the project brief and download any required files from pCloud.
3. **Break down the task:** Where necessary, divide complex assignments into smaller activities.
4. **Prioritize your work:** Consider task priority, deadlines, and dependencies on other activities.
5. **Execute the task:** Use the appropriate tools, software, equipment, and procedures.
6. **Review your output:** Check that your work meets the requirements before preparing it for submission.

For example, a task involving embedded software development may require reviewing hardware specifications, writing firmware, testing functionality, and preparing the resulting source files.

The exact activities depend on the requirements of the assignment.

## 3. Organizing Your Working Files

Employees are expected to maintain an organized working environment while executing assigned tasks.

Since project resources are downloaded from pCloud and worked on locally, proper file organization helps prevent confusion, missing files, and accidental loss of work.

### Recommended Practices

- Create a dedicated working folder for each project.
- Keep downloaded reference materials separate from files you are actively modifying.
- Use clear and descriptive filenames.
- Preserve the folder structure of projects containing multiple related files.
- Maintain appropriate local backups of important work in progress.
- Avoid mixing files belonging to different projects.

Where a task involves source code, circuit designs, or other technical files, ensure that all related dependencies and supporting resources are retained.

> [!TIP] File Organization  
> A well-organized working folder makes it easier to locate files, troubleshoot problems, and prepare complete deliverables for submission.

### Managing Source Code with GitHub

NASCOMSOFT uses **GitHub** to manage and store source code developed for company projects.

Unlike general project documents and resources stored on pCloud, project source code is maintained in repositories under the company's GitHub account.

Employees assigned programming or other code-related tasks are expected to:

1. Create a personal [GitHub account](https://github.com/signup) if they do not already have one.
2. Contact the designated GitHub Administrator to request access to the company's GitHub repositories.
3. Create or access the appropriate project repository once the necessary permissions have been granted.
4. Develop and manage their code using the appropriate repository.
5. Ensure that their completed code is uploaded (pushed) to the company repository as part of their deliverables.

> [!IMPORTANT] Source Code Submission  
> Source code developed for company projects must be stored in the appropriate company GitHub repository, not solely on an employee's personal computer or GitHub account.
> 
> Uploading source code to a repository does not automatically mean the task has been completed. The work remains subject to review and verification by the Project Manager.

For instructions on creating an account, accessing repositories, and submitting code, see [[getting started with gitHub\|getting started with gitHub]].

## 4. Working on Shared Projects

A single project may involve several employees working on different tasks simultaneously.

For example, one employee may be responsible for firmware development while another handles circuit design, testing, research, or documentation.

Each employee is expected to focus on their assigned responsibilities while maintaining effective communication with others involved in the project.

### Collaboration Guidelines

- Understand how your task contributes to the overall project.
- Coordinate with other employees when your work depends on theirs.
- Inform the Project Manager when a dependency affects your ability to proceed.
- Avoid modifying another employee's work without authorization.
- Communicate relevant technical findings or changes that may affect other project activities.

**Remember:** Working on the same project does not necessarily mean employees have the same tasks or responsibilities.

### Identifying Project Contributors

Each Project Brief will contain information about employees who have contributed to the project and the work they were responsible for.

This information helps employees identify who to contact when they need clarification about previous work, technical decisions, or existing project components.

Before contacting another employee:

1. Review the relevant Project Brief to identify previous contributors.
2. Check the available project resources and documentation on pCloud.
3. Identify the employee responsible for the relevant work.
4. Contact the employee if additional clarification or technical information is required.
5. Inform the Project Manager if the issue remains unresolved or affects your assigned task.
    
> [!TIP] Make Use of Existing Project Knowledge  
> Before starting work on an existing project component, review what has already been done and identify the employees involved.
> 
> This helps prevent duplicated effort, unnecessary rework, and the loss of important project knowledge.

## 5. Managing Deadlines and Reporting Challenges

Employees are expected to make reasonable efforts to complete assigned tasks within their specified deadlines.

If you encounter a challenge that may affect your progress, communicate it as early as possible.

Examples include:
- Missing or inaccessible project resources
- Unclear task requirements
- Technical difficulties or unexpected errors
- Dependencies on another employee's work
- Equipment or software limitations
- Other circumstances that may prevent timely completion

### What to Do When You Encounter a Challenge

1. Identify the problem and how it affects your assigned task.
2. Check whether the issue can be resolved using the available project resources or documentation.
3. Notify the Project Manager if the problem cannot be resolved or may affect the deadline.
4. Explain what you have attempted and what assistance or clarification you require.
5. Continue with other available activities where possible.
    
> [!IMPORTANT] Do Not Wait Until the Deadline  
> If you identify a problem that may prevent task completion, report it promptly rather than waiting until the deadline or the next weekly meeting.

A separate guide will explain the company's formal procedure for reporting task-related complaints and blockers.

## 6. Preparing Your Deliverables

Before submitting your work, ensure that it is complete and meets the requirements of your assigned task.

Depending on the assignment, deliverables may include:

- Source code and configuration files
- Circuit diagrams, schematics, or design files
- Research reports and technical documents
- Testing results and supporting evidence
- Hardware design files
- Other outputs specified in your assignment
    
### Before Submission

Check that:

1. The assigned work has been completed according to the provided instructions.
2. The necessary files are present and can be opened.
3. Relevant tests or checks have been performed where applicable.
4. Files are properly named and organised.
5. All requested deliverables have been included.
    
Documentation may also be assigned as a separate task, depending on the project requirements.

> [!info] Completion and Approval  
> Finishing your assigned work does not automatically mean the task has been marked as completed.
> 
> Your deliverables must be submitted for review, and the Project Manager is responsible for verifying the work and updating its completion status.

## 7. Weekly Task Review Meetings

NASCOMSOFT conducts weekly task review meetings on **Mondays** to assess progress and discuss outstanding work.

During these meetings, employees are expected to:

- Present or explain work completed during the previous week.
- Discuss tasks that remain incomplete.
- Explain challenges or circumstances affecting task completion.
- Provide updates on ongoing activities.
- Clarify any issues requiring management attention.

Employees should be prepared to demonstrate their progress or provide relevant supporting information when requested.

These meetings help the Project Manager assess progress, identify challenges, and coordinate subsequent activities.

## 8. Frequently Asked Questions

**What if I am assigned multiple tasks?**

Review their priorities and deadlines, organize your work accordingly, and contact the Project Manager if you need clarification on which task should take precedence.

**What if I do not understand my assignment?**

Contact the Project Manager for clarification before beginning the task.

**What if I cannot complete my task before the deadline?**

Notify the Project Manager as soon as you identify the difficulty. Explain the problem, your progress, and any assistance required.

**Can I work on tasks assigned to another employee?**

Only when instructed or authorized by the Project Manager.

**What if I finish my task before the deadline?**

Prepare and submit your deliverables for review. You do not need to wait until the next Monday meeting.

**Who determines whether my task is completed?**

The Project Manager reviews the submitted work and confirms whether the task meets the assigned requirements.
